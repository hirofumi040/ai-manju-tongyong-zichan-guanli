# AIGC教学项目结论总览

整理日期：2026-11-02  
项目：AIGC教学PPT设计  
教学主题：《AI漫剧通用资产管理体系：结合 Obsidian 与 GitHub 实战》

## 一、项目主线

项目讨论形成三层工作：

1. **资产生产研究**：人物身份与造型、场景空间与多视角等视觉资产怎么设计和复用。
2. **资产管理方案**：人工选择与分组，AI协助编号、版本、命名和归档，Obsidian 管状态，GitHub 做版本记录与备份。
3. **系统和教学落地**：完成教学材料，并把流程放入 Obsidian 与 GitHub 实际运行。前两层已有较多方案；真实资产批量入库和完整联动仍待实测。

## 二、资产管理方案

### 人和 AI 的分工

| 环节 | 当前项目方向 |
|---|---|
| 放入素材 | 人工把生成后的图片放入指定区域或白板。 |
| 判断关系 | 人工按资产类型和资产身份分组；是否属于同一资产由人决定。 |
| 资产归档 | AI根据人工分组协助生成唯一编号、简单版本号、文件名、Markdown资产卡和变更记录，并给出归档位置。 |
| 正式确认 | 人工审核归档结果并决定是否进入正式资产库。身份关系不明确时先询问，不擅自合并。 |

**用户最后明确的分工是“人来负责放入图片和分组，AI来负责归档”。**早期“AI自动分类、移动白板、全自动监控”等说法不能当作当前方案或已实现功能。AI直接操作 Obsidian 文件和 Canvas 的完整能力尚未实测。

### 白板、状态和编组

- 方案方向是一张主要的 Obsidian Canvas 管理白板，使用五种状态：草稿、测试、正式、历史、废弃。
- 正式资产按两层组织：先按资产类型，再按唯一资产 ID 分组。
- 正式资产需要人工确认；历史版和废弃版的含义不同，历史版保留可追溯性，废弃版表示停止使用。
- 以上是项目设计方向，不代表 Obsidian 白板已经建成并投入运行。

### 编号、版本和共享

项目讨论中使用的资产前缀示例为：

| 类型 | 前缀示例 |
|---|---|
| 人物 | `CHR` |
| 场景 | `SCN` |
| 道具 | `PRP` |
| 音频 | `AUD` |
| 分镜 | `SHT` |
| 视频 | `VID` |

- 一个资产使用一个永久 ID；服装、表情、姿态等可作为该资产的派生内容或版本关联管理。
- 用户要求简化版本记录，后续方案改用 `V01`、`V02` 等格式；更早提出的三段式语义版本号不再作为当前简化方案。
- 编号的数字位数和完整命名语法尚未最终锁定，例子不应误写成已发布的全局标准。
- 用户确认建立公共资产库，由不同项目按资产 ID 和具体版本共享调用，避免各项目重复保存同一份公共资产。该联动尚未实测。

### 生成提示词的边界

用户明确更正：**生成资产时使用的提示词不纳入资产归档，不作为独立资产，也不纳入 GitHub 资产版本管理。**管理对象是最终资产及必要的身份、状态、版本和来源信息。早期把提示词库或 `PRM` 作为资产类别的方案已被这项更正取代。

项目可以在教学中讲如何写提示词，但“提示词是制作方法”不等于“提示词要作为资产归档”。具体保留哪些工具、模型、审核或授权元数据，仍需在实施模板中决定。

## 三、人物资产研究

### 角色资产包的研究框架

研究讨论把角色从单张展示图扩展为可重复调用的一组视觉资料：文字设定、人物主设图、正侧背三视图、面部特写、基础表情、服装变体、姿态或镜头适配图。核心问题是不同图像和镜头中仍能识别为同一角色。

建议的制作顺序是先建立中性主设，再扩展面部和三视图、表情、服装与姿态；验证身份稳定后再考虑正式入库。该流程是研究方案，尚无证据证明已经为一套角色完整跑通。

### 面部 DNA 研究

对话形成了 F01–F07 的第一版研究框架：

| 模块 | 研究对象 | 第一版参数数 |
|---|---|---:|
| F01 | 脸型与骨相 | 16 |
| F02 | 眉毛 | 12 |
| F03 | 眼睛 | 17 |
| F04 | 鼻子 | 14 |
| F05 | 嘴唇 | 12 |
| F06 | 五官组合与空间关系 | 13 |
| F07 | 由整体结构派生的视觉风格 | 10 |
| 合计 |  | 94 |

这 94 项是对话中的第一版目录，不代表每个角色都必须填写 94 个精确数值，也不是医学或学术统一标准。项目本身仍需要统一测量点、摄影视角、比例定义和样本，再通过实际生成与人工判断校准。风格标签描述视觉印象，不用于推断现实人物性格；不同五官组合可产生不同风格，不设唯一审美模板。

用户把角色案例方向从动漫改为仿真人，并提出项目角色资产采用真人照片质感。该要求仅记录为本项目的视觉方向，不扩展为总办或其他项目的通用规定。

## 四、场景资产研究

### 空间一致性的核心

场景资产不是若干张相似的室内图，而是同一空间的多种表达。研究重点包括墙体、门窗、固定家具的空间拓扑和相对位置，以及材质、色彩、光线和装修风格。人物、摄影机、时间、天气和可移动小物件可以按剧情变化；空间身份锚点应保持可解释的一致。

### 用户确认的模板方向

用户选择同时建立**版式模板和生成提示词模板**。形成的六联图版式为：

- 16:9 横版；上排两张大图：空间定位图、场景主视觉。
- 下排四张不同观察角度的小图；小图不能重复主视觉。
- 六张图应属于同一空间；门窗、墙体、家具、材质和色彩关系彼此对应。
- 最终图面要求无标题、文字、编号、摄像机图标、边框和白色留白，图片铺满。

### 生成与验收思路

先定义空间结构和固定家具，再确定主视觉；四个角度分别生成时沿用同一组空间与视觉参考，之后检查空间布局、门窗、固定家具、风格和视角是否互相冲突。二维参考图不能保证重建出准确三维几何；遇到严格空间连续性要求时，Blender 白模是对话提出的辅助方案，尚未证明已用于实际流程。

**未决细节：**另一段研究把“摄影机定位图”列为核心产出，而最终六联图模板没有明确给它单独留格，并禁止画面内出现摄像机图标。摄影机定位图如何与六联图并存，仍需确定；本包不擅自改写为已解决。

旧对话声称客厅和书房图片已生成并保存 10 张，但本次没有重新打开那些文件，也没有把它们纳入资料包，因此这里只记录为聊天报告。

## 五、Seedance 2.5 与资产参考

用户确认本项目讨论的是 Seedance 2.5。官方资料说明它可组合文本、图片、视频和音频输入，并支持人物、物体、场景、风格、运动和白模等参考；白模视频可与主体、场景或道具图片等参考配合使用。见[火山引擎 Seedance 2.5 提示词指南](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=zh)和[字节 Seedance 2.5 产品页](https://seed.bytedance.com/zh/seedance2_5)（查阅日期：2026-11-02）。

这些资料可以支持“资产图可作为参考材料”的表述，但不能推出杜绝换脸、完全可控、失败率下降 70% 或提升平台推流等保证。项目课件的第二页不应扩展成无关的视频模型教程；用户也明确不希望把审核验收规范说明加到该页。

## 七、当前优先补齐的实测

1. 选一套角色资产，按主设、视图、面部、表情或服装变体流程做完并记录身份一致性检查。
2. 选一个场景，按空间定位图、主视觉和多视角模板整理并检查空间连续性，同时决定摄影机定位图的位置。
3. 在 Obsidian 中实测人工放图分组、AI生成归档资料、人工审核、五状态流转和公共资产调用。
4. 在 GitHub 中实测版本提交、资产 ID 和版本引用；大文件的存储方式另行决定。
5. 取得并检查旧 PPT、ZIP、场景图及面部 DNA Excel 实物，再把状态从“聊天报告/待确认”更新为“已核验”。

以上是项目内的研究和设计方向。它们没有修改或替代总办规范。
